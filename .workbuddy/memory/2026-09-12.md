## AI 配图体积过大：接入 Tinify 压缩
- 需求：AI 出图（1024 PNG 单张 ~1.2MB）太大，需在 Node 侧压缩。
- 方案：在 `models-server/src/services/imageService.js` 引入 `tinify` 包，`resolveImage` 对 AI 图与图库兜底图统一调 `compressImage()` 压缩后再返回 base64。
  - `compressImage` 延迟读 `TINIFY_API_KEY`（与 SILICONFLOW 同款延迟读模式，避开 ESM import 早于 dotenv）；
  - < 200KB 不压（省每月 500 次免费额度）；压缩后≥原体积或任何异常都回退原图，绝不阻断生成。
- 密钥：`models-server/.env` 加 `TINIFY_API_KEY=...`（已配，`.env` 已被 git 忽略，不会误提交）。
- 验证（隔离 3301）：实测 1 张 1.24MB PNG → 308KB，**缩小 75.6%**，`compressionCount=1`（密钥有效）；`resolveImage` 集成返回 provider=ai 已压缩图。
- 影响：4 张图整体响应从十几 MB 降到 ~1.2MB，顺带缓解 WebClient 64MB 缓冲压力；需**重启 Node 服务(3300)** 让新代码生效。

## AI 出图尺寸源头缩小
- 原来封面/内嵌都用了 `SILICONFLOW_COVER_SIZE`（1024x1024），且 `articleService` 调 `resolveImage` 没传 `size`，导致 `INLINE_SIZE` 配置一直没生效。

- 改动：
  - `articleService` 现从 `getImageConfig()` 取 `coverSize`/`inlineSize` 并分别透传给封面/内嵌的 `resolveImage`（封面/内嵌尺寸真正可独立配置）。
  - `.env`：`SILICONFLOW_COVER_SIZE`、`SILICONFLOW_INLINE_SIZE` 均改为 **768x1024**（比 1024x1024 少 25% 像素）。

## 小程序：登录过期处理重构（去掉 reLaunch 强跳登录页）
- 原逻辑：`api/request.js` 401 → 清态 + toast → 1.5s 后 `uni.reLaunch` 到登录页；登录页登录成功又 `switchTab` 首页 → **两次丢上下文**（清空页面栈 + 落回首页），用户刚点的操作白点。
- 关键前置事实（决定方案）：后端 `/api/v1/wx/login` 是 `@Anonymous`，`WxUserServiceImpl.wxLogin` 用 `selectUserByOpenId` **命中老用户即复用同一账号换新 token**；`updateUserInfo` 只在入参非空时更新（空 profile 静默重登**不污染昵称头像**）。`TokenService.verifyToken` 剩余 ≤20 分钟自动续期 → token 只会在"离线超 30 分钟无任何请求"时过期。**结论：静默重登可无感接回，绝大多数过期根本不需要用户操作。**
- ⚠️ **静默重登必须校验 userId 一致**：`selectUserByOpenId` 为 null 时会走 `createWxUser` **直接建新号并送 20 积分**。只用账号密码注册过、openid 为空的老用户会被静默切成空账号。本地存 `userId` 作基准，不一致即中止转人工登录。
- 落地（三层递进，新增模块 `src/utils/session.js`）：
  1. 静默重登（uni.login → /wx/login）成功 → 调用方**自动重放原请求**（`_retried` 标记，每请求最多一次，防死循环）；
  2. 失败才弹窗（重新登录 / 稍后再说）；「重新登录」用 `navigateTo`（**不 reLaunch**），登录成功后 `navigateBack` 回原页并重放；「稍后再说」释放挂起请求降级游客，并有 60s 静默期防反复弹窗；
  3. 兜底：页面栈满 → `redirectTo`；用户 120s 不处理 → 定时释放挂起请求，避免永久悬挂。
- 并发控制：`recovering` 单飞（并发 401 共享同一 promise 与同一弹窗）；`pendingRequests` 挂起队列 + `releasePendingRequests()` / `hasPendingRequests()` 供登录页判断回跳。
- 改动文件：新增 `src/config/server.js`（抽离 SERVER_BASE/BASE_URL，避免 request.js ↔ session.js 循环依赖，request.js 原样 re-export 保持既有 import 路径可用）、`src/utils/session.js`；
  改 `src/api/request.js`（401 分流 + `setSessionHooks` 同步 Pinia）、`src/store/user.js`（新增 `setUserId`，各登录入口写入；**logout 不清 userId**，留作校验基准）、`src/pages/login/index.vue`（`finishLogin()` 统一收尾 + onShow/onUnload）。
- 校验：`@vue/compiler-sfc` + `@babel/parser` 全过；`npm run build:mp-weixin` 构建通过（5s，产物含 `utils/session.js`）。
  构建里的 `Circular chunk: store/user -> api/user -> api/request -> store/user` 警告是**改动前就存在**的既有循环，与本次无关。
