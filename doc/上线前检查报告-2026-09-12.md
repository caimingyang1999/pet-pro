## 二、阻断项

### 🔴 阻断项 1：生产接口地址不合规（已修复）

**问题**：`.env` 中 `VITE_PROD_SERVER_BASE=https://8.152.194.141:8080`，存在三重问题：

1. **微信小程序「服务器域名」不支持 IP 地址**，必须是已备案域名；
2. **不支持非 443 端口**，`:8080` 无法通过域名校验；
3. 实测该端口**从外网根本不通**（见下表），真机必然请求失败。

**实测数据**（`8.152.194.141`）：

| 端口 | 结果 |
|------|------|
| 80 | ✅ 开放 |
| 443 | ✅ 开放 |
| **8080** | ❌ **连接超时** |

**已完成的修复**：
- `.env` → `VITE_PROD_SERVER_BASE=https://coof.xin`
- 已重新构建，产物中 `8.152.194.141` 已彻底清除，仅保留 `https://coof.xin`

**新地址验证结果（全部实测通过）**：

| 检查项 | 结果 |

### 🔴 阻断项 2：生产后端是整改前的旧版本（必须部署）

**问题**：生产环境下，**所有游客可浏览的公开接口全部返回 401**：

```
GET /api/v1/articles/list  → {"msg":"...认证失败，无法访问系统资源","code":401}
GET /api/v1/banner/list    → 401
GET /api/v1/shop/categories→ 401
GET /api/v1/shop/products  → 401
GET /api/v1/config/features→ 200 ✅（说明生产版本部分较新）
```

**本地代码是好的**，`@Anonymous` 注解齐全：

| 文件 | `@Anonymous` 数量 |
|------|------------------|
| `controller/article/ArticleController.java` | 2 处 |
| `controller/wx/BannerController.java` | 1 处 |
| `controller/shop/ShopController.java` | 3 处 |

**结论**：本地已整改，生产未部署 → 服务器上跑的是中间版本。

**为什么这是阻断项**：微信审核已明确驳回过的原因 2 就是「未先体验浏览功能服务就要求授权」。若以此版本提审，游客打开首页**看不到任何内容**，**必然再次驳回**。

**修复动作**（需在服务器上执行，AI 无法代办）：
1. 本地打包：`mvn clean package -Pprod`（或按现有部署流程构建）
2. 上传并替换服务器上的 jar
3. 重启后端 8080 服务
4. 复验命令（应返回数据而非 401）：
   ```bash
   curl -sS https://coof.xin/api/v1/articles/list?pageNum=1\&pageSize=2
   curl -sS https://coof.xin/api/v1/banner/list
   ```
5. 同时确认生产库中**文章、轮播图、商品、分类有真实数据**（空列表同样会被判定为「无法体验」）
