# 宠迹小程序 · 功能合规改造说明

> 改造日期：2026-09-10
> 改造目标：从「社交-笔记」转型为「宠物健康管理工具」，满足微信**个人主体**小程序审核要求

---

## 一、改造背景

原小程序包含「用户发布动态 / 评论 / 点赞 / 关注 / 用户主页」等用户生成内容（UGC）与社交互动能力，
被微信审核判定为「社交-笔记」类目，个人主体无法开通。

本次改造**彻底移除前端全部社交能力**，将产品定位收敛为纯工具属性：
用户管理自己的宠物档案、记录体重与成长点滴、浏览平台发布的养宠知识、用积分兑换商品、使用智能问答。

**改造红线（已严格遵守）**：
1. 前端无任何用户之间的互动（无评论、无点赞、无关注、无粉丝、无私信）
2. 前端无用户生成内容的公开展示（用户创建的一切内容均为私有）
3. 后端接口与数据表**全部保留**（未来升级企业主体可直接复用，无需重写）

## 四、新增工具功能

### 4.1 体重记录 `pages/pet/weight.vue`
- 支持多宠物切换；从首页快捷工具进入时自动选中第一只爱宠
- 原生 canvas 绘制**体重趋势折线图**（含 Y 轴刻度与网格线）
- 顶部汇总：当前体重 / 较上次变化（增红减绿）/ 记录次数
- 底部记录明细列表，支持删除
- 新增记录面板：体重、记录日期（日期选择器）、备注

### 4.2 成长相册 `pages/pet/album.vue` + `pages/pet/album-edit.vue`
- **仅自己可见**，页面顶部常驻隐私提示：「成长相册仅你自己可见，不会对外公开」
- 支持添加照片（最多 9 张）、标题、描述、记录日期
- 图片上传复用项目既有 `/common/upload` 通道
- **无点赞、无评论、无分享、无公开**，编辑页删除操作为软删除

### 4.3 健康记录 `pages/pet/health.vue`
- 概览：爱宠数 / 疫苗记录数 / 待办提醒数
- **健康提醒**：自动从每只爱宠的疫苗 `nextDate` 计算，到期前 30 天进入提醒列表
  - 已逾期（红）/ 7 天内（橙）/ 30 天内（蓝）三级配色
- 爱宠档案卡片：头像、疫苗条数、最新体重，三个快捷入口（体重记录 / 成长相册 / 宠物档案）
- 入口：首页「疫苗提醒」快捷工具、「我的」页「健康记录」菜单、「我的宠物」详情页顶部

### 4.4 宠物详情页
新增「健康记录快捷入口」条：体重记录 / 成长相册 / 健康提醒。

## 八、新增接口

完整定义见 `doc/API接口文档.md`。

| 模块 | 接口 | 是否登录 |
|------|------|:--------:|
| 体重记录 | `POST /api/v1/pet/weight` | 是 |
| | `GET /api/v1/pet/{petId}/weight` | 是 |
| | `DELETE /api/v1/pet/weight/{id}` | 是 |
| 成长相册 | `POST /api/v1/pet/album` | 是 |
| | `GET /api/v1/pet/{petId}/album` | 是 |
| | `GET /api/v1/pet/album/{id}` | 是 |
| | `PUT /api/v1/pet/album/{id}` | 是 |
| | `DELETE /api/v1/pet/album/{id}` | 是 |
| 养宠知识（用户端） | `GET /api/v1/articles/list` | **否（@Anonymous）** |
| | `GET /api/v1/articles/{id}` | **否（@Anonymous）** |
| 养宠知识（后台） | `GET/POST/PUT/DELETE /api/v1/admin/articles` | 是（`article:*` 权限） |

**安全约束**：所有健康记录接口均以 `userId` 做归属校验；
成长相册的非本人访问一律返回「无权查看他人的相册记录」，避免内容泄露。

> 后端改动**未触碰** `ruoyi-framework` / `ruoyi-common` 核心，全部落在 `ruoyi-system` 与 `ruoyi-admin`。

### ⚠️ 上传前务必先清空 dist 目录

uni-app 的构建**不会自动删除已移除页面的旧产物**。本次改造中发现 `dist/build/mp-weixin` 里
仍残留 `pages/user/home.js`、`pages/mine/follows.js`、`pages/index/detail.js` 等**上次构建遗留的社交页面代码**。
这些文件不会被注册到 `app.json`（审核员点不到），但**会被打进小程序包**，存在被静态扫描标记的风险。

正确做法：

```bash
cd pettrace-miniapp
rm -rf dist/build/mp-weixin        # 先清空
npm run build:mp-weixin            # 再构建
# 用微信开发者工具导入 dist/build/mp-weixin 上传
```

本次已代为清理，但**后续每次删页面后都要先清 dist 再构建**。

## 十、未来升级企业主体后如何恢复

社交能力的代码与数据表都完整保留，恢复成本极低：

1. 在 `src/pages.json` 的 `pages` 数组中重新注册 6 个页面
2. tabBar 第三项从 `pages/pet/list` 改回 `pages/chat/index`（如需恢复助手 tab）
3. 后端 `GET /config/features` 把 `adviserEnabled` 置为 `true`（恢复 AI 助手，无需发版）
4. 修复已下架页面中的跳转方式：
   - `pages/chat/history` 跳对话页已改为 `redirectTo`（对话页不再是 tabBar 页面），恢复 tabBar 时需改回 `switchTab`
   - `pages/mine/index.vue` 的 `handleMenuClick` 已支持 `item.tab` 标记走 `switchTab`，直接复用即可
5. 协议正文（`src/config/legal.js`）需同步补充 UGC 相关条款
