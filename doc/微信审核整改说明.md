## 二、原因 1：去除混淆腾讯官方元素

### 问题定位
三处页面使用了微信官方图标（`weixin-fill` / `weixin`）与微信品牌绿渐变按钮，按钮文案写作"**微信**手机号登录"，容易被认定为仿冒或混淆腾讯官方账号体系。

### 具体改动

| 文件 | 改动前 | 改动后 |
|------|--------|--------|
| `src/pages/login/index.vue` | 按钮文案"微信手机号登录" + `u-icon weixin-fill` | 文案"**手机号快捷登录**" + 📱 图标（橙色品牌底色） |
| `src/pages/login/index.vue` | "其他登录方式"下微信绿渐变圆标 + 文案"微信登录将直接使用手机号授权" | 改为橙色品牌色圆标 + 📱 图标 + 文案"使用手机号快捷登录，无需记忆密码" |
| `src/pages/login/register.vue` | "微信手机号一键注册 / 登录" + `weixin-fill` + 微信绿圆 | "**手机号快捷注册 / 登录**" + 📱 图标 + 橙色圆 |
| `src/pages/mine/index.vue` | "微信手机号登录" + `Icon name="weixin"` | "**手机号快捷登录**" + 📱 图标 |
| 全局样式 | `linear-gradient(135deg, #5FC967, #39B54A)` 微信品牌绿 | 统一替换为产品品牌渐变 `$gradient-primary` |

### 复审要点
- 全包已无 `weixin-fill` 用法，无微信品牌绿按钮，无"微信"字样的登录提示文案。
- 保留的唯一"微信"相关能力是 `uni.login({ provider: 'weixin' })`（用于换取登录 code），属正常技术调用，界面上无任何腾讯官方视觉元素。

## 三、原因 2：改为"游客可浏览、按需登录"模式

### 问题定位（两层原因）

**前端**：`src/App.vue` 的 `onLaunch` / `onShow` 中，只要本地无 token 就 `uni.reLaunch` 到登录页，导致一打开小程序就被强制推到登录页。

**后端**：`SecurityConfig` 为 `.anyRequest().authenticated()`，且浏览类接口（`/api/v1/posts/list`、`/api/v1/banner/list`、`/api/v1/shop/*`、`/api/v1/follows/*`）均未标注 `@Anonymous`，游客访问必然 401。

### 前端改动

| 文件 | 改动说明 |
|------|----------|
| `src/App.vue` | **删除** `checkLoginAndRedirect()` 强制跳转逻辑，仅保留恢复本地登录态与拉取功能开关 |
| `src/utils/auth.js` | **新增**统一登录引导模块：`isLoggedIn()`、`goLogin()`、`requireLogin(actionText)`、`goUserAgreement()`、`goPrivacyPolicy()` |
| `src/api/request.js` | 401 处理分流：**曾登录过**（token 失效）→ 清登录态 + 提示 + 跳登录页；**游客**（本地无 token）→ 静默失败，**绝不跳转** |
| `src/utils/index.js` | 废弃的 `checkLogin()` 不再跳转 `/pages/mine/index`（tabBar 页 `navigateTo` 本身会失败），改为纯提示 |
| `src/pages/index/index.vue` | 点赞 / 发布动态 → 改为 `requireLogin()` 弹窗征询；浏览列表、进详情、看评论**无需登录** |
| `src/components/PostCard.vue` | 关注按钮 → `requireLogin('关注 TA')` |
| `src/pages/index/detail.vue` | 点赞、发表评论 → `requireLogin()`；浏览详情与评论列表无需登录 |
| `src/pages/user/home.vue` | 关注、点赞 → `requireLogin()` |
| `src/pages/shop/detail.vue` | 兑换商品 → `requireLogin('兑换商品')`；浏览商品详情无需登录 |
| `src/pages/chat/index.vue` | 提问 → `requireLogin('向养宠助手提问')` |

`requireLogin` 的交互：弹出"需要登录"对话框，提供 **【去登录】/【再逛逛】** 两个选项，由用户自行选择，不做强制跳转。

### 后端改动（`ruoyi-admin`）

浏览类接口增加 `@Anonymous` 注解，使其在 Spring Security 放行（依托 `PermitAllUrlProperties` 自动收集）：

| 文件 | 开放的接口 |
|------|------------|
| `controller/post/PostController.java` | `GET /api/v1/posts/list`、`GET /api/v1/posts/{postId}`、`GET /api/v1/posts/{postId}/comments`、`GET /api/v1/posts/search/users` |
| `controller/wx/BannerController.java` | `GET /api/v1/banner/list` |
| `controller/shop/ShopController.java` | `GET /api/v1/shop/categories`、`GET /api/v1/shop/products`、`GET /api/v1/shop/products/{productId}` |
| `controller/user/UserFollowController.java` | `GET /api/v1/follows/check/{followeeId}`、`GET /api/v1/follows`、`GET /api/v1/follows/followers`、`GET /api/v1/follows/count` |

**兼容处理**：新增私有方法 `currentUserIdOrNull()`，匿名上下文下 `SecurityUtils.getUserId()` 会抛 `ServiceException`，此处统一 try/catch 返回 `null`，让"游客态"逻辑自然降级（不返回点赞/关注状态，但不报错）。

> 遵守 `AGENTS.md` 约束：**未修改** `ruoyi-common` / `ruoyi-framework` 等框架核心代码，改动全部位于业务控制器。
> 数据库 Mapper 早已支持 `currentUserId` 为 `null`（`PetPostMapper.xml` 中有 `jdbcType=BIGINT` 显式声明），无需改动 SQL。

**仍需登录的接口（保持不变）**：发布/删除动态、点赞、评论、关注取关、积分签到、收货地址、兑换下单、我的动态/点赞、用户信息等 —— 均已 `@PreAuthorize("@ss.isAuthenticated()")`。

## 四、原因 3：补齐《用户协议》与《隐私政策》

### 问题定位
`goAgreement()` / `goPrivacy()` 仅执行 `showToast('用户协议开发中')`，审核员点击后无法查看实质内容，判定"暂无法体验核实"。

### 具体改动

| 文件 | 说明 |
|------|------|
| `src/config/legal.js` | **新增**：存放《宠迹用户服务协议》《宠迹隐私政策》完整正文（分章节结构化数据） |
| `src/pages/common/agreement.vue` | **新增**：协议渲染页，通过 `?type=user|privacy` 区分文档 |
| `src/pages.json` | 注册路由 `pages/common/agreement` |
| `src/pages/login/index.vue` | 协议链接改为真实跳转；**新增协议勾选**（未勾选时按钮改为普通视图，不唤起手机号授权） |
| `src/pages/login/register.vue` | 同上，账号注册与手机号快捷注册均增加协议勾选前置校验 |
| `src/pages/mine/index.vue` | 协议链接改为真实跳转；新增协议勾选 |

### 协议内容覆盖要点
- **用户协议**：协议接受与变更、账号注册与使用、用户行为规范、宠物档案与动态内容、积分与商城规则、服务变更与终止、免责声明、知识产权、法律适用、联系方式。
- **隐私政策**：明确的收集清单（**手机号、头像昵称、宠物档案、动态与互动内容、收货地址、设备与日志、剪贴板**）、使用目的、Cookie/本地缓存说明、共享与转让（微信开放平台 / 物流 / 云服务）、存储与安全、**用户五项权利**（访问更正、删除、撤回同意、注销账号、获取副本）、未成年人保护、政策更新、联系方式。

## 五、原因 4：小程序类目问题（需运营侧处理，非代码）

审核反馈第 4 条属于**小程序服务类目与资质**问题，代码无法解决。请在小程序管理后台确认：

1. 进入 **微信公众平台 → 设置 → 基本设置 → 服务类目**，核对当前类目是否为实际经营内容（宠物社区 + 积分商城）。
2. 若涉及"宠物"相关类目，可能需要补充相应资质或选择更贴合的类目组合。
3. 若整改中新增/调整了功能（如新增智能问答），需同步更新类目与《用户隐私保护指引》。
4. 完成上述调整后，再连同代码一起重新提交审核。

## 六、提交审核前的必查项（人工执行）

- [ ] **配置《用户隐私保护指引》**：微信公众平台 → 设置 → 基本设置 → 服务内容声明 → 用户隐私保护指引。必须勾选/填写实际使用的隐私接口：
  - **手机号**（用于 `getPhoneNumber` 手机号快捷登录）
  - **相册（仅上传）**（用于 `uni.chooseImage`：发布动态配图、头像上传、宠物档案照片）
  - 未使用的权限（如位置）**不要声明**。已从 `manifest.json` 中移除未使用的 `scope.userLocation` 权限声明。
- [ ] 核查 `manifest.json` 的 `mp-weixin.appid` 为正式提交所用 AppID。
- [ ] 确认 `.env` 中 `VITE_PROD_SERVER_BASE` 指向生产环境 HTTPS 域名，且该域名已在小程序后台"开发设置 → 服务器域名"中配置。
- [ ] 提审版本中养宠助手模块开关 `VITE_ADVISER_ENABLED=false`（提审期关闭，通过后由后端 `GET /config/features` 远程开启）。
- [ ] 后端重新编译打包并部署（本次涉及 `ruoyi-admin` 四个控制器）。
- [ ] 小程序端 `npm run build:mp-weixin` 后，用微信开发者工具导入 `dist/build/mp-weixin` 上传。
- [ ] **提审备注**中建议写明：已支持游客免登录浏览首页、商城、动态详情；仅在点赞/评论/发布/关注/兑换等场景由用户自主选择登录；已提供完整《用户协议》《隐私政策》。
